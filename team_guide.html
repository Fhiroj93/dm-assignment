01

Combined project overview

What every team member should understand.

What problem are we solving?

A graph is a collection of entities and their relationships. Our system finds nodes that behave differently from the majority. In a network-security example, nodes could be computers, edges could be connections, and unusual nodes could indicate compromised devices.

Core idea: assign every node an anomaly score. A higher score means the node is more different from the normal or pseudo-normal profile.

Research connection

The project is inspired by From Few-Shot to Zero-Shot: Towards Generalist Graph Anomaly Detection. The paper proposes generalist models that can work across unseen graph datasets.

Our version demonstrates the central concepts in a simpler way. It is not a full reproduction of the paper’s ARC and ARCzero deep-learning experiments.

Nodes

Entities such as users, devices, accounts, transactions, or papers.

Edges

Relationships such as communication, friendship, transfer, or citation.

Features

Numerical behaviour information stored for each node.

04

Methods explained simply

Use these explanations during the technical viva.

Baseline detection

Calculate the average feature profile of normal nodes. Measure how far each node is from it. A larger distance produces a higher anomaly score.

normal_profile = average(normal_node_features) anomaly_score = distance(node_features, normal_profile) rank nodes by anomaly_score

Few-shot detection

Few-shot means learning from a small number of examples. We use five known normal nodes as context, calculate their profile, and compare every node with it.

context = five_known_normal_nodes context_profile = average(context_features) score every node against context_profile

Zero-shot detection

Zero-shot has no labelled normal examples. We use a median feature profile to find typical nodes, call them pseudo-normal context, and calculate final scores.

typical_profile = median(all_features) pseudo_context = most_typical_nodes score every node against pseudo_context

Important clarification

Is this a GNN? Not in the current simplified version. We use NetworkX for graph representation and feature-distance scoring. A future version could add GCN, GraphSAGE, residual GNN layers, feature alignment, and cross-attention like the paper.

07

Likely lecturer questions

Answer directly and honestly.

What is graph anomaly detection?

Finding nodes or relationships that behave differently from the majority of a graph.

Why is graph data different from tabular data?

Graph data contains both attributes and relationships. A node may be unusual because of its features, neighbours, or network position.

Why use a synthetic dataset?

It is small, controlled, reproducible, and easy to visualize. It lets us demonstrate the algorithm without difficult data cleaning.

What is few-shot versus zero-shot?

Few-shot uses a small number of labelled normal examples. Zero-shot has no labelled examples and selects typical nodes automatically.

How is the anomaly score calculated?

We calculate standardized feature distance between each node and a normal or pseudo-normal profile. Larger distance means larger anomaly score.

Why did every method achieve 1.00?

The synthetic anomalies were deliberately generated with clearly different feature values. This confirms the implementation works but does not represent real-world performance.

Is this exactly the paper’s model?

No. It is a simplified educational implementation inspired by the paper. The paper uses feature alignment, residual GNN encoding, cross-attention, and many real-world experiments.

What would you improve next?

Use real datasets, add GCN or GraphSAGE, implement learned feature alignment and cross-attention, test multiple datasets, and report runtime and generalization.

What is the practical use?

Cybersecurity monitoring, fraud detection, suspicious account discovery, social-network analysis, and unusual transaction detection.

How do you avoid data leakage?

Do not use evaluation labels to select context or train the detector. Selection and preprocessing should use only permitted information.

08

Limitations and future scope

Understanding limitations shows project maturity.

Current limitations

  • Dataset is artificial and intentionally easy.
  • Detector uses feature distance rather than a learned GNN.
  • Only one small graph is evaluated.
  • Complex categorical and missing features are not handled.
  • Perfect metrics cannot be generalized to real-world performance.

Future improvements

  • Use public transaction, citation, or network datasets.
  • Add GCN, GraphSAGE, or GAT layers.
  • Implement learned feature alignment.
  • Add residual graph encoding and cross-attention.
  • Compare with established GAD baselines.
  • Measure runtime, memory, and out-of-domain generalization.
